# Loading and Cloudflare delivery

**Decision:** Render the homepage from the initial application bundle; keep policy content lazy. The homepage is the main entry point, and a second JavaScript discovery round trip delayed its first render. Revisit if other application routes become the main product.

**Decision:** Use deferred GSAP reveals and native CSS slideshow transitions instead of loading a second animation engine for the homepage. Leaflet and its stylesheet now load together only for a configured workshop map. Typography uses WOFF2 compression with the original glyphs and outlines; `python scripts/optimize-fonts.py` regenerates these assets with fonttools and brotli. Revisit if new animation or map functionality requires different dependencies.

Railway caches fingerprinted `/assets` files for one year with `immutable`; HTML remains revalidated. Unversioned media retain shorter browser caching so content can be updated.

Hero images have AVIF variants with WebP fallbacks. The first AVIF is preloaded; the next image is requested at low priority after a two-second delay, avoiding immediate competition with the first render. `npx tsx scripts/optimize-hero-assets.ts` regenerates variants from the existing WebP references.

Run `npm run build:cloudflare` to prepare `work/cloudflare-build`, then `wrangler pages deploy work/cloudflare-build --project-name wills-group --branch main`. The artifact includes standalone policy HTML, hash-authorized structured data, security headers and immutable hashed asset caching. The informational site uses browser-only project briefs; commerce remains disabled. Railway remains the canonical origin and API host. No custom domain is assumed to be owned.

**Decision:** Serve normalized, compressed gallery previews instead of full gallery photos while scrolling. Each of the 33 designs has 360 × 450, 720 × 900 and 1080 × 1350 AVIF/WebP variants in a consistent 4:5 frame. Responsive selection follows the actual single-column mobile layout. Uncropped, compressed full views load on opening a design. Interior images, hero images and brand icons also use smaller derivatives. Original supplied files remain intact.

**Decision:** Encode all twelve public clips as H.264 Main/yuv420p with 48 kbit/s AAC audio, 24 fps, a maximum 720-pixel edge without upscaling, CRF 30 and a 400 kbit/s video ceiling. Fast-start MP4 puts metadata before video data; each clip has a lightweight poster. No video request occurs before clip selection. Alternative: adaptive multi-rendition streaming adds operational complexity for these short clips. Revisit if duration, traffic or playback measurements justify a streaming service.

**Decision:** Railway serves the optimized clips on both sites; images and frontend assets on the Cloudflare mirror remain on its CDN. Live verification and the official Pages documentation confirm Pages returns HTTP 200 for Range requests rather than 206. Using the existing range-capable Railway origin supports seeking and Safari playback without adding a streaming service or R2 bucket. The Cloudflare artifact excludes original and optimized MP4 payloads; CSP permits only the configured HTTPS media origin. `VITE_VIDEO_ORIGIN` can select another verified range-capable host. Revisit when Pages supports byte ranges or playback traffic justifies dedicated video infrastructure. Reference: https://developers.cloudflare.com/pages/configuration/serving-pages/

Regenerate images with `npm run media:optimize -- --images`; regenerate clips with `FFMPEG_PATH` set to a verified FFmpeg binary and `npm run media:optimize -- --videos`. Both operations save measured sizes to ignored `work/optimized-media-report.json`. The media regression checks enforce matching dimensions, the 64 KiB 720-pixel AVIF budget, smaller video files and metadata before the payload. Encoding tools are not production runtime dependencies.

Only the supplied public MP4 responses permit cross-origin embedding through Cross-Origin-Resource-Policy. API, account and other response security controls remain in place.

The Pages project uses Direct Upload. Uploads from this connection encountered resets/timeouts with the CLI's default concurrent 40 MiB batches. Windows native HTTPS requests to the Pages asset and deployment APIs completed the release, using sequential 4 MiB batches and credentials held only in memory. The installed CLI and repository runtime were not modified. Successful upload and HTTP/browser verification are required for every release. Rollback uses the previous verified Railway deployment or Cloudflare Pages production deployment.

Performance budgets: no map or second animation engine in initial requests, no video requests before selecting a clip, first image prioritized, lazy responsive gallery images, no horizontal overflow, reduced-motion content visible, and target cold-mobile LCP below 2.5 seconds. Synthetic measurements use a 390 × 844 viewport, cold cache, 1.6 Mbps download, 150 ms added latency and 4× CPU slowdown. Connection variability means measurements from this machine are diagnostic, not a guarantee for every visitor.

Measured media payloads for this release: the 33 standard 720 × 900 AVIF previews total 929,329 bytes (28,161 bytes average; 48,026 bytes maximum), compared with 4,161,990 bytes for the previous full-size gallery WebPs. The twelve public clips total 41,764,605 bytes compared with 103,249,218 original bytes, a 59.5% reduction. The longest clip remains 125 seconds; files range up to 7,140,116 bytes. All clip durations differ by less than 0.03 seconds after encoding. These are file-size measurements, not a claim of instantaneous page loading.

Font delivery uses 21 KB Latin subsets of the original supplied faces, with Unicode ranges selecting full source WOFF2 files for extended characters. The four initial faces total 84,496 bytes instead of 137,896 bytes (38.7% smaller). The subset generator verifies source advance widths and retains all OpenType layout features; the combined faces retain the original character coverage.
